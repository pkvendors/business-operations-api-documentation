# API Glossary

## Introduction

This glossary defines common technical terms used throughout the Business Operations Management System (BOMS) API documentation. It is intended to help developers and users understand API concepts, terminology, and functionality.

## API Terminology

| Term | Definition |
|---|---|
| **API** | Application Programming Interface. A set of rules and protocols that allows different software applications to communicate and exchange information. |
| **REST** | Representational State Transfer. An architectural style for designing web services that communicate using standard HTTP methods. |
| **Endpoint** | A specific URL through which an API resource or function can be accessed. |
| **HTTP** | Hypertext Transfer Protocol. A communication protocol used to transfer information between clients and servers. |
| **JSON** | JavaScript Object Notation. A lightweight data format used to exchange structured information between applications. |
| **Authentication** | The process of verifying the identity of a user or application attempting to access an API. |
| **Authorization** | The process of determining what resources or actions an authenticated user or application is permitted to access. |
| **Request** | Information sent from a client application to an API to retrieve, create, update, or delete data. |
| **Response** | Information returned by an API after processing a client request. |
| **Payload** | The data transmitted within an API request or response, commonly formatted as JSON. |
| **Parameter** | An input value supplied in an API request to identify a resource, filter results, or modify request behavior. |
| **Bearer Token** | A security credential included in an HTTP request header to authorize API access. Anyone possessing a valid bearer token may use it according to its assigned permissions. |
| **HTTP Method** | An action that specifies what operation an API should perform, such as GET, POST, PUT, PATCH, or DELETE. |
| **GET** | An HTTP method used to retrieve information from an API. |
| **POST** | An HTTP method used to submit data to an API, commonly to create a new resource. |
| **PUT** | An HTTP method generally used to replace an existing resource with updated information. |
| **PATCH** | An HTTP method used to modify selected fields or properties of an existing resource. |
| **DELETE** | An HTTP method used to request the removal of a specified resource. |
| **Status Code** | A three-digit HTTP response code indicating the result of an API request. |
| **200 OK** | An HTTP status code indicating that a request was successfully processed. |
| **201 Created** | An HTTP status code indicating that a new resource was successfully created. |
| **400 Bad Request** | An HTTP status code indicating that the request contains invalid or missing information. |
| **401 Unauthorized** | An HTTP status code indicating that valid authentication credentials are missing or invalid. |
| **403 Forbidden** | An HTTP status code indicating that the client does not have permission to access the requested resource. |
| **404 Not Found** | An HTTP status code indicating that the requested resource could not be located. |
| **500 Internal Server Error** | An HTTP status code indicating that the server encountered an unexpected problem while processing the request. |
| **Base URL** | The primary address of an API to which endpoint paths are appended. |
| **Resource** | An object or data item managed by an API, such as an employee, department, customer, or order. |
| **Header** | Additional information included in an HTTP request or response, such as authentication credentials or content type. |
| **Content-Type** | An HTTP header that identifies the format of the data being transmitted, such as application/json. |
| **CRUD** | An acronym for Create, Read, Update, and Delete—the four basic operations used to manage data. |
| **API Key** | A unique credential used to identify an application or authorize its access to an API. |
| **JWT** | JSON Web Token. A compact token format used to securely transmit information between parties. |
| **OAuth 2.0** | An authorization framework that allows applications to obtain limited access to protected resources without sharing a user's password. |
| **Validation** | The process of checking submitted data to ensure it meets required formats, rules, and conditions. |
| **Error Handling** | The process of identifying, reporting, and managing errors that occur during API operations. |
| **Versioning** | The practice of assigning versions to an API so changes can be introduced while managing compatibility with existing applications. |

## Purpose of This Glossary

This glossary provides a consistent reference for terminology used in the BOMS API documentation. It supports communication between developers, technical writers, business analysts, and other stakeholders.
